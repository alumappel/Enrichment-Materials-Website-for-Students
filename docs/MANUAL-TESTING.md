# מדריך בדיקות ידניות

הבדיקות מיועדות לביצוע שלך בדפדפן רגיל, ובהמשך בהטמעה האמיתית במוודל. לא הופעלה שליטה בדפדפן לצורך בדיקת המערכת. הבדיקות האוטומטיות בודקות את הלוגיקה ואת תהליך GitHub מול תשובות מדומות; הן אינן מחליפות את הבדיקות כאן.

אם בדיקה נכשלת, רשמו את כתובת העמוד, הדפדפן וגרסתו, רוחב התצוגה, הזום, הפעולות שביצעתם, התוצאה הצפויה והתוצאה בפועל. צרפו את נוסח השגיאה, כותרת הפריט וה־revision כאשר רלוונטי. אין לצרף מפתח GitHub או סיסמה. לאחר תיקון, חזרו על הבדיקה שנכשלה ועל הפעולות הקשורות אליה.

## הכנה

1. הפעילו `Start.cmd` שבתיקיית `website`, או את קיצור ההפעלה בתיקיית הפרויקט הכללית. את הפקודות בהמשך המדריך יש להריץ מתוך `website`. היכנסו ל־http://localhost:8080/ ולעורך ב־http://localhost:8080/editor.html . הכניסה הראשונית: `lecturer` / `enrichment2026`.
2. למבחני טעינה, עצרו את השרת עם Ctrl+C והריצו `node scripts/serve.mjs --fixture 31`. קובץ התכנים האמיתי לא משתנה; השרת מחזיר מאגר זמני נפרד של 31 חומרים פעילים, המשויכים ל־Unity ולפיתוח אתרי אינטרנט. יש בו את כל שבעת הסוגים ופריט אחרון עם מילת המפתח ״פריט אחרון לבדיקה״. מאגר הבדיקה כולל מילון מונחים לבדיקות המקבילות; המילון במאגר האמיתי ריק בהתאם לייבוא.
3. אפשר להחליף את 31 ב־0, 1, 15, 16 או 30. לכל מספר, עצרו והפעילו מחדש את השרת. לבדיקת הנתונים הרגילים, הפעילו שוב `Start.cmd` בלי פרמטר.
4. לשלב GitHub השתמשו תחילה במאגר בדיקה. השלימו את ההגדרה שב־README והזינו מפתח רק בשדה ההגדרות בעורך.

## החיפוש, התפריט והכרטיסיות המעודכנים

בדיקת תיקון 2026-10-06: פתחו את סוג התוכן ולחצו פעמיים על השם סרטון. אחרי הלחיצה הראשונה הסימון מופיע והתוצאות משתנות; אחרי השנייה הסימון מתבטל. בשתי הלחיצות התפריט נשאר פתוח. חזרו על כך באייקון, בתיבה עצמה ובכמה סוגים רצופים, גם בדפדפן המובנה. התפריט צריך להיסגר בלחיצה מחוץ לו, ב־סיום, ב־Escape או ב־Tab החוצה, ולהישאר פתוח בזמן בחירה. אם שם הסוג עדיין סוגר אותו, תעדו את הכתובת המלאה, הדפדפן, הסוג והאם התיבה או מונה הסוגים השתנו לפני הסגירה.

בדיקה חוזרת לתקלה בלחיצה על שם סוג: אחרי רענון העמוד, פתחו סוג התוכן ולחצו על המילה סרטון: התיבה מסומנת. לחצו שוב על אותה מילה: הסימון מתבטל. חזרו על שתי הלחיצות דרך האייקון ודרך תיבת הסימון עצמה. בכל דרך הבחירה צריכה להתחלף פעם אחת, התוצאות להתעדכן והתפריט להישאר פתוח. בחרו ובטלו כמה סוגים בזה אחר זה; חזרו גם דרך Space במקלדת, בנייד ובקישור ?course=unity. אם שתי לחיצות על אותו שם אינן מסמנות ואז מבטלות, רעננו עם Ctrl+Shift+R ודווחו על הסוג ועל דרך הלחיצה. אין לצפות לסגירת התפריט באמצע בחירה או לקריסת לשונית.

## העורך במצב ההדגמה

1. נסו שם משתמש וסיסמה שגויים ואז את הפרטים התקינים. אפשר להדביק סיסמה ולהשתמש במנהל סיסמאות. צפויה הודעה עברית ברורה בכניסה שגויה. אם נכשלת כניסה תקינה, בדקו `config.json` ואת מדריך ההפעלה.
2. פתחו **פריט חדש** ונסו לפרסם בלי מילוי. צפויים סיכום שגיאות, הודעות ליד השדות ומיקוד בשדה השגוי הראשון. מלאו כותרת, תיאור, סוג, URL ושני קורסים. התצוגה המקדימה מתעדכנת; בנייד היא אחרי הטופס. אם שדה מתאפס, רשמו את הפעולה שגרמה לכך.
3. עדכנו את תצוגת ההדגמה. הפריט מופיע פעם אחת בעורך. רענון מחזיר את הנתונים המקוריים. המאגר הציבורי אינו משתנה במצב הדגמה. אם המערכת מציגה ״פורסם באתר״ במצב זה, זו תקלה.
4. הזינו קישור שכבר קיים. צפויות האפשרויות **עריכת הפריט הקיים** או **המשך כפריט נפרד**. אם נוצר עותק בלי בחירה, רשמו את הקישור ואת כותרות הפריטים.
5. ערכו פריט: הכותרת משתנה, המזהה ותאריך ההוספה נשמרים. העבירו לארכיון ואחר כך שחזרו; אין מחיקה לצמיתות. עריכת פריט בארכיון משאירה אותו בארכיון. אם סדר ההוספה השתנה בלי תיקון תאריך, תעדו את הפריט.
6. הוסיפו קורס, שנו שם, ונסו שם או מזהה כפולים. המזהה נעול אחרי הפרסום הראשון. מחולל ההטמעה תומך בכמה קורסים ובגובה לבחירה. אם קישור ישן נשבר לאחר שינוי שם, העבירו את המזהה והכתובת.
7. הוסיפו קבוצת מונחים עם לפחות שני מונחים, ונסו קבוצה עם מונח אחד. החיפוש בעורך משתמש במילון המעודכן. אם ביטוי רב־מילי אינו נמצא, רשמו את הביטוי ואת הקבוצה.
8. שנו טופס בלי פרסום ונסו לבטל, לצאת או לרענן. צפויה התרעה, ואין שמירת טיוטה מתמשכת. אם שינויים אבדו בלי התרעה, רשמו את פעולת היציאה.

## פרסום אמיתי, כשלי רשת והתנגשויות

1. לאחר חיבור GitHub, נסו מפתח שגוי ואז תקין. הודעת שגיאה לא מאפסת את הטופס; אין להעתיק מפתח לדיווח. אם החיבור נדחה, בדקו תוקף, הרשאות Contents, מאגר, ענף ונתיב.
2. פרסמו פריט לשני קורסים. צפויה שמירה במאגר, מצב המתנה לפריסה ולבסוף **פורסם באתר**. פתחו את האתר הציבורי ורעננו: הפריט מופיע פעם אחת באיחוד הקורסים. אם האימות מתעכב, לחצו **בדיקת מצב**, בדקו את Actions ואת `revision` בקובץ הציבורי. אין להסיק שהשמירה נכשלה רק מפני שהפריסה ממתינה.
3. בזמן פרסום נסו לחיצה חוזרת. הכפתור נעול עד לסיום. אם נוצרו שני פריטים, רשמו את המזהים ומזהה הפרסום.
4. נתקו רשת לפני פרסום וחברו שוב. הטופס נשאר. ניסיון חוזר בודק קודם אם הפעולה כבר נשמרה. אל תלחצו על יצירת פריט חדש כדי להתאושש. אם יש ספק, בדקו מצב ואת היסטוריית המאגר לפני ניסיון נוסף.
5. פתחו שתי לשוניות עורך וחברו כל אחת למאגר. ערכו באחת ושמרו. פרסמו בשנייה בלי רענון. צפויה עצירה והצגת הגרסה העדכנית, ללא דריסה. לחצו **טעינת הגרסה החדשה**, השוו והחילו שוב. בדקו גם מצב שבו הראשונה מעבירה פריט לארכיון והשנייה משנה רק כותרת: השינוי בכותרת לא יחזיר אותו אוטומטית למאגר. אם קרתה דריסה, הפסיקו ניסיונות ותעדו את שני השינויים; אפשר לשחזר דרך היסטוריית GitHub.
6. פרסמו שינוי לאחר שכבר צפיתם באתר ורעננו לאחר סיום הפריסה. צפויה גרסה חדשה בלי ניקוי מטמון ידני. אם יש גרסה ישנה, השוו את `revision` באתר למזהה בעורך, ובדקו שה־HTML וה־assets נפרסו יחד.
7. כדי לבדוק כשל טעינה ציבורי, הפעילו חסימת רשת בדפדפן ורעננו. צפויה הודעת כשל וכפתור ניסיון נוסף. אם בדיקה מקומית אינה מושפעת ממצב Offline, השתמשו ב־Request blocking לחסימת `data/content.json`, ואז הסירו את החסימה. אין לקבל הודעת קורס ריק במקום כשל.

## הטמעה במוודל

לאחר העלאה ל־HTTPS, העתיקו קוד מהמחולל בממשק הקורסים. בדקו גבהים 600 ו־900, קורס אחד וכמה קורסים, מחשב וטלפון. הגובה נשאר קבוע; רק אזור החומרים גולל, ובמסגרת קצרה או בזום גבוה התוכן גולל יחד. אין שתי גלילות אנכיות בתוך האתר. הוספת חומרים אינה מגדילה את המסגרת, וקישור נפתח בלשונית חדשה.

אם מוודל מסיר את iframe, בדקו הרשאות והגדרות תוכן עם מנהל מוודל. אם המסגרת ריקה, בדקו גם קישור ישיר ו־HTTPS. אם הקישור הישיר עובד וההטמעה אינה עובדת, תעדו גובה, רוחב ושיטת ההטמעה. ניתן להשתמש בקישור ישיר עד לתיקון.

תנאי הקבלה הוא שכל התרחישים הרלוונטיים עוברים במחשב, בטלפון ובהטמעה האמיתית, כולל מקלדת וקורא מסך. היעד הוא WCAG 2.2 AA; מדריך זה אינו הצהרה שהושלמה בדיקת התאמה מלאה.
