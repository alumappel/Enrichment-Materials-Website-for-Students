# מערכת חומרי העשרה

המערכת פותחה לפי מסמך האפיון, ב־HTML, CSS ו־JavaScript ונילה עם Bootstrap 5.3.8 RTL. היא כוללת מאגר סטודנטים ועורך אישי בעברית. קובץ התכנים האמיתי `data/content.json` כולל 121 פריטים פעילים, תשעה קורסים ושבעה סוגי תוכן, בגרסת הייבוא `import-20261005-002`. מסמך האפיון וחומרי העבודה הנלווים נשארים בתיקיית הפרויקט הכללית, מחוץ לתיקיית `Enrichment Materials Website for Students`.

## תיקייה להעלאה ל־GitHub

תיקיית `Enrichment Materials Website for Students` היא תיקיית המאגר העצמאית. היא כוללת את קובצי האתר, קוד המקור, כלי הבנייה, הבדיקות, הספריות והרישיונות, והתיעוד הנדרש לתחזוקה. יש להעלות **את כל תוכן התיקייה לשורש המאגר**; `index.html` צריך להיות בשורש המאגר ולא תחת תיקייה נוספת בשם `Enrichment Materials Website for Students`.

הנתיב לקובץ התכנים ב־GitHub נשאר `data/content.json`, ו־Pages מוגדר לפרסום מ־`/(root)`. קובצי חומרי לימוד שאליהם מפנים קישורי התכנים נמצאים ב־`resources/` בתוך תיקיית האתר, ונכללים בהעלאה. מסמך האפיון, הגיליון המקורי ותוצרי ההכנה שב־`outputs/` נשארים בתיקיית הפרויקט הכללית ואינם נכללים בהעלאה.

## הפעלה מקומית

לחצו פעמיים על `Start.cmd` שבתיקיית `Enrichment Materials Website for Students`, או על קיצור ההפעלה `Start.cmd` בתיקיית הפרויקט הכללית. השאירו את החלון פתוח, ופתחו:

- מאגר הסטודנטים: http://localhost:8080/
- העורך: http://localhost:8080/editor.html
- קורס יחיד: http://localhost:8080/?course=unity
- שני קורסים: http://localhost:8080/?course=unity,web-development

שם המשתמש הראשוני הוא `lecturer` והסיסמה הראשונית היא `enrichment2026`. אפשר לשנות אותם באמצעות `node scripts/set-login.mjs`. ההתחברות היא מחסום מקומי פשוט לפי האפיון; הרשאת הכתיבה למאגר נקבעת על ידי מפתח GitHub.

לסיום, לחצו Ctrl+C בחלון ההפעלה. אם אתם מעדיפים מסוף, פתחו אותו בתוך `Enrichment Materials Website for Students` והריצו `npm run build` ואז `npm start`. את כל פקודות הבנייה, הבדיקות והנתונים במדריך הזה יש להריץ מתוך `Enrichment Materials Website for Students`. Node.js כבר מותקן במחשב הזה; אין צורך להתקין חבילות npm. אל תפתחו את `index.html` בלחיצה כפולה: קריאת JSON מחייבת שרת מקומי או אתר ב־HTTPS.

אם פורט 8080 תפוס, סגרו הפעלה קודמת של המערכת או הריצו ב־PowerShell: `$env:PORT=8081` ואחר כך `npm start`. הכתובות יהיו עם 8081.

## מצב ההדגמה

העורך מתחיל במצב הדגמה כאשר GitHub אינו מחובר, וטוען את התכנים האמיתיים. אפשר לבדוק הזנה, עריכה, ארכיון, שחזור, קורסים ומילון. הפעולה נקראת **עדכון תצוגת ההדגמה**. השינוי תקף בזיכרון של העורך בלבד עד רענון, ואינו משנה את קובץ התכנים או את המאגר הציבורי. אין שמירה של טיוטות מתמשכות.

## התכנים שיובאו

121 הפריטים נשמרו כפי שנמסרו, כולל מזהים, שיוכים, תאריכים ועוגני קישורים. קורסי `design`, `learning-skills`, `other` ו־`computer-science` נכללים במאגר. הקורס `other` מופיע גם כשהוא ריק. `keywords` ו־`synonymGroups` נשארו ריקים בהתאם למקור; חיפוש עדיין פועל בכותרות ובתיאורים, ואפשר להרחיב את המילון בעורך בהמשך.

הסוג **קובץ** (`file`) זמין במאגר, במסננים ובעורך. תשעת הקבצים נמצאים ב־`resources/`. אפשר להזין קישור פנימי כגון `/resources/scenes-001.pptx` לצד קישורי HTTP(S). המערכת מתאימה קישור כזה לבסיס האתר: ב־GitHub Pages תחת `/REPO/`, הוא נפתח מתוך `/REPO/resources/`. אין לשנות את הקישורים ב־JSON לנתיב של המחשב המקומי.

סדר הפריטים בקובץ נשמר. התצוגה ממשיכה למיין לפי תאריך ההוספה ולחשוף 15 פריטים בכל פעם; הכלי החדש נוסף בראש הרשימה בגלל תאריך ההוספה שלו. נתוני הבדיקות הנפרדים נמצאים ב־`tests/fixtures/sample-content.json`, וניתן להפעיל מאגר בדיקה זמני עם `node scripts/serve.mjs --fixture 31` בלי לשנות את התכנים האמיתיים.

## חיבור לפרסום ב־GitHub

1. צרו מאגר ציבורי והעלו את כל תוכן תיקיית `Enrichment Materials Website for Students` לשורש המאגר. הקפידו לכלול גם את הקבצים `.nojekyll` ו־`.gitignore`. קובצי האתר, קוד המקור וכלי התחזוקה כבר מרוכזים בתיקייה הזו.
2. בהגדרות המאגר, הפעילו GitHub Pages באמצעות **Deploy from a branch**, בחרו `main` ו־`/(root)`. העלאה של קובץ התכנים לאותו ענף תפעיל את הפריסה. חכו להשלמת הפריסה הראשונית.
3. צרו Fine-grained personal access token המוגבל למאגר הזה, עם הרשאת **Contents: Read and write**. הרשאות **Actions: Read** ו־**Pages: Read** הן רשות ומאפשרות זיהוי מוקדם יותר של כשל פריסה. אין צורך בהרשאת שינוי Workflows. אם הענף מוגן מפני כתיבה ישירה, יש לאפשר את דרך הפרסום הזו או לבחור ענף מתאים.
4. היכנסו לעורך, פתחו **הגדרות חיבור**, והזינו את בעל המאגר, שם המאגר, ענף הפרסום, נתיב הקובץ `data/content.json`, כתובת Pages עם `/` בסוף והמפתח. לחצו **בדיקה וחיבור**.
5. המערכת תקרא את הנתונים העדכניים מהמאגר. פרטי המאגר נשמרים מקומית; **המפתח אינו נשמר** בקבצים, ב־localStorage או ב־sessionStorage. לאחר רענון יש להזין אותו מחדש.
6. לאחר פרסום תופיע קודם הודעת שמירה במאגר. **פורסם באתר** מופיע רק לאחר שקובץ הנתונים באתר מציג את מזהה הפרסום החדש. אם האימות מתעכב, השתמשו ב־**בדיקת מצב** ובקישור לפריסה. שמירה מוצלחת אינה הוכחה שהפריסה הסתיימה.

אם החיבור חסר או נדחה, הטופס נשאר במסך. אפשר לתקן את החיבור ולפרסם שוב. אם המאגר השתנה בלשונית אחרת, המערכת עוצרת לפני דריסה ומציעה טעינת גרסה חדשה. לפני אישור, השוו את הערכים שמוצגים. השדות שערכתם נשארים בטופס; שדות שלא שיניתם ומצב הארכיון מתעדכנים מהמאגר. יש ללחוץ שוב על פרסום לאחר בדיקה.

אם החיבור נכשל לפני קבלת תשובה, העורך מבדיל בין חוסר חיבור, זמן המתנה, כשל רשת ותשובה שלא ניתן לקרוא. הקונסול מציג אבחון מוגבל ללא מפתח הגישה או פרטי הבקשה. מפתח עם רווחים או תווים שאינם תקינים נדחה לפני השליחה. הוראות בדיקה והמשך טיפול נמצאות ב־[מדריך הבדיקות הידניות](docs/MANUAL-TESTING.md#אבחון-חיבור-github--עדכון-2026-10-06). לאחר שינוי קוד, בנו מחדש והעלו את ה־HTML ואת assets יחד כדי לקבל את קובצי הקוד עם חתימות התוכן החדשות.

מקורות להקמה: [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site), [עדכון קובץ דרך GitHub API](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents).

## החלפת התכנים הראשוניים

החליפו את `data/content.json`, בהתאם ל־[תיאור מבנה הנתונים](docs/DATA-FORMAT.md). לאחר ההחלפה הריצו:

```text
npm run test:data
node scripts/revise-data.mjs
```

הפקודה הראשונה בודקת את כל הנתונים. השנייה יוצרת `revision` חדש ומעדכנת `updatedAt`. שמרו את מזהי הקורסים הקבועים כדי שקישורים קיימים ימשיכו לפעול. אין צורך לשנות HTML או JavaScript בעת החלפת התוכן. כל שינוי בקוד או בעיצוב דורש `npm run build` והעלאה של ה־HTML והקבצים המעודכנים מ־`assets/` יחד.

## בדיקות

`npm test` בודק חיפוש, סינון, נתונים, תאריכים, מטמון ופרסום דרך API מדומה. `npm run build` מפיק קובצי הפצה עם מזהה תוכן בשם. הבדיקות אינן מפעילות דפדפן.

בדיקות התצוגה, המקלדת, קורא המסך וההטמעה במוודל מיועדות לביצוע ידני על ידי המרצה: [מדריך הבדיקות הידניות](docs/MANUAL-TESTING.md). המדריך מפרט גם מה לעשות כשבדיקה נכשלת. טרם בוצע אימות חזותי או אימות נגישות מלא בדפדפן, ולא בוצע פרסום למאגר חי.

## קבצים ותחזוקה

- `src/index.html`, `src/editor.html`, `src/styles.css`: קובצי המקור של המסכים והעיצוב.
- `src/core.mjs`: חיפוש, סינון, מבנה נתונים, זמן ישראל ומחולל הטמעה.
- `src/public.mjs`, `src/editor.mjs`: התנהגות ממשקי הסטודנטים והעורך.
- `src/github.mjs`: כתיבה עם SHA, התאוששות מתשובה שאבדה ואימות הפרסום.
- `src/dom.mjs`: יצירת רכיבים באמצעות טקסט, בלי הצגת תוכן משתמש כ־HTML.
- `src/visuals/learning-buddies.png`: איור הדמויות המקורי עם רקע שקוף.
- `docs/VISUAL-DESIGN.md`: הפלטה, שילובי הצבעים, הקו המנחה לאיורים והפרומפט המקורי.
- `scripts/build.mjs`: שמות CSS, JS, גופנים ואיור עם SHA-256; גם שינוי בתלות מעדכן את שם קובץ ה־JS המייבא אותה.
- `vendor/`: עותקים מקומיים של Bootstrap, משפחת UIcons אחת וגופן Rubik עם הרישיונות. אין תלות ב־CDN בהפעלה.
- `docs/THIRD-PARTY.md`: גרסאות ומקורות. הקרדיט החינמי ל־Flaticon מופיע בתחתית, בהתאם להנחיה המעודכנת שלך.

אין Service Worker או מטמון אופליין. נתוני JSON והגדרות נקראים עם `no-store` ופרמטר בקשה ייחודי בכל טעינה. הסיסמה המקומית אינה מפתח GitHub, והיא אינה מגינה על קובצי האתר הציבוריים.
